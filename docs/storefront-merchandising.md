# Storefront merchandising controls

The dedicated `/dashboard/merchandising` editor requires `content.update/all` on every read and write. It replaces the old dashboard form that offered hero/sourcing copy no longer displayed by the product-led storefront. Legacy content records and endpoint remain for compatibility; an existing announcement is used until the new settings record is saved.

The versioned record controls the announcement, main hero, up to two hero-side products, category navigation and digital discovery. Product placements have an enabled flag, plain-text title, selection strategy, optional exact category restriction, maximum product count, ordered manual product IDs and explicit fallback (`newest` or `hide`). Strategies are featured, newest, currently discounted or manual. No sales/rating claims are inferred.

Selections run against the **already filtered catalog**, never a global pool. Products must have a real ID/title, valid price and sufficient stock for their minimum order quantity; unlimited digital inventory follows existing catalog rules. Side products exclude every selected hero product. Discovery accepts digital products only. Active-discount selection verifies a real priced promotion and its expiration. Automatic placements prefer usable product imagery before applying the limit, excluding the known mismatched wheat-field photo from usable imagery. Within that priority, newest uses creation time, then product ID for deterministic ties. The public placement includes its strategy so client load-failure handling can preserve explicit manual order. Manual selection preserves administrator order; missing/out-of-stock/out-of-filter pins are skipped. Empty placements hide, and fallback only fills from eligible products in the same category/filter scope. All returned products use the public projection with digital delivery secrets removed.

Writes validate types, lengths, strategy/fallback values, duplicate pins, bounded limits and referenced products. Active manual pins must match the placement category and digital-only scope. Pins for disabled or non-manual placements are cleared, so a removed listing cannot block switching to automatic selection. Optimistic compare-and-swap prevents lost edits; failed saves never advance the browser form version. Storage errors block the editor, while the public storefront falls back to validated defaults.

Selection is a snapshot of each page request. Stock and campaign state can change after rendering; checkout remains authoritative. The hero remains manually controlled rather than silently adding automatic motion. This iteration does not implement targeting by personal data, inferred popularity, A/B testing, arbitrary HTML/CSS injection, or a full drag-and-drop layout builder.

## Section ordering

The editor now stores a complete `section_order` alongside the same settings version: product showcase (hero and side cards together), category navigation, product catalog, digital discovery and sourcing help. Every permitted section must appear exactly once; unknown/duplicate/missing keys are rejected, so ordering cannot remove the catalog or inject arbitrary components. Older records inherit the existing default sequence. Visibility remains governed by each existing section's eligibility/settings.

Accessible Move up/Move down controls change draft order and announce the new position. Reset restores the default draft; Publish is still required. The storefront renders the sequence in actual DOM order, keeping visual, keyboard and reading order aligned. Hidden/empty sections create no spacer wrapper. A function ref preserves the single category rail element and observer lifecycle when its block moves. Existing filtering, product-selection, dialogs and checkout paths are unchanged.
