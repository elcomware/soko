# Settings page checklist
Reference: Dashboard/Index.vue. New focused settings page uses existing site-container, workspace-panel, field, button/button-navy, form-error and workspace-feedback classes and semantic tokens. Page header h1, sections h2; every input has a label. Inertia useForm submission disables pending controls and surfaces server feedback. Permissions default deny, own/all clearly distinguished; self editing unavailable. Brand curated local fonts only. Payment preferences explicitly show not activated, never collect credentials. Responsive stacked fields; keyboard-native select/button controls; no decorative KPI cards.

Admin refinement: separate panel-specific dirty state, explicit discard confirmation and live identity preview. Account switches require discarding unsaved permission scopes; merchant navigation uses the same route guard. Native fieldsets freeze editing while saving, and callbacks acknowledge submitted/server snapshots without falsely marking later edits saved. Browser Back is not canceled: allow-listed drafts recover from Inertia history, scoped to actor and merchant/target account and rechecked against current permissions. No payment secrets are stored; payments remain NOT LIVE. Successful save or discard clears remembered drafts. Tested late edits, server normalization, rejected redirects and scoped recovery.
